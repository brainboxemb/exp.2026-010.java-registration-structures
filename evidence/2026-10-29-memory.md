- PooledAvlRanking deliberately preallocates 512 Node objects plus a Node[] pool.

## Interpretation

This measurement reinforces the JMH choice.

Pooled AVL does provide a somewhat faster pure rank lookup and a ~0.5 µs faster 500-row
snapshot on the desktop runner, but it costs:

- ~22 KiB extra retained heap in the complete state;
- 512 preallocated Node objects;
- substantially more custom balancing/pool code;
- slower ranking mutation roundtrips.

SortedArrayRanking therefore remains the preferred ~500-registration design.

TreeMap is neither the smallest nor the fastest and also allocates during ordinary rank reads.
It remains only a standard-library comparison.

## Caveat

These figures are for OpenJDK 17 with its object layout/compressed-reference configuration on
the GitHub x86 runner. Exact Java 8 / Pi object sizes may differ.

The relative structural difference cannot disappear entirely, however: the sorted candidate is
one primitive array, while the AVL candidate necessarily retains hundreds of node objects and
references.

Pi qualification remains the final hardware/runtime gate.
